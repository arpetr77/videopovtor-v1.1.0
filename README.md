# Видеоповтор боя

Веб-приложение (PWA) для телефона. Телефон стоит на штативе и смотрит на площадку. Судья командует «Бой» — идёт запись, «Стоп» — клип сохраняется на телефон, а по кнопке «Повтор» открывается замедленный просмотр с покадровой перемоткой.

Бэкенда нет. Все видео и настройки хранятся только на устройстве. Сборка не нужна: чистые HTML, CSS и JavaScript (ES-модули), без внешних библиотек.

---

## 1. Как выложить в интернет

Нужен адрес **с HTTPS**: без него браузер не даст доступ к камере. Все три варианта ниже дают HTTPS автоматически.

### Вариант А. Netlify (проще всего, без командной строки)
1. Зайдите на https://app.netlify.com/drop (регистрация бесплатная).
2. Перетащите **папку проекта целиком** (ту, где лежит `index.html`) в окно браузера.
3. Через несколько секунд получите адрес вида `https://что-то.netlify.app`. Откройте его на телефоне.

### Вариант Б. Cloudflare Pages
1. https://dash.cloudflare.com → Workers & Pages → Create → Pages → **Upload assets**.
2. Назовите проект, загрузите папку проекта, нажмите Deploy.
3. Адрес будет вида `https://имя.pages.dev`.

### Вариант В. GitHub Pages
1. Создайте репозиторий на https://github.com (публичный).
2. На странице репозитория: **Add file → Upload files**, перетащите **содержимое** папки проекта (файлы и папки `js`, `icons` — не саму внешнюю папку), нажмите Commit.
3. **Settings → Pages → Source: Deploy from a branch → Branch: main / (root) → Save**.
4. Через 1–2 минуты сайт откроется по адресу `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

> Приложение использует только относительные пути, поэтому работает и в подпапке (как на GitHub Pages).

### Как выпустить новую версию
Измените `CACHE_VERSION` в начале файла `sw.js` (например, на `videopovtor-v1.0.1`) и загрузите файлы заново. Телефон скачает обновление при следующем открытии и покажет подсказку. Не обновляйте приложение во время записи.

## 2. Установка на телефон

**iPhone (Safari, iOS 16.4+):** откройте адрес в **Safari** → кнопка «Поделиться» → «На экран Домой» → «Добавить». Запускайте приложение с иконки.

**Android (Chrome):** откройте адрес в Chrome → меню ⋮ → «Установить приложение» (или «Добавить на главный экран»).

При первом запуске разрешите доступ к камере (и микрофону, если нужен звук). После первой загрузки приложение работает без интернета.

## 3. Как пользоваться

- **БОЙ** (зелёная) — начать запись, кнопка станет красной **СТОП**. Экран получает красную рамку, телефон коротко вибрирует (если поддерживается).
- **СТОП** — закончить запись. Клип сохраняется автоматически. Имя файла: `ГГГГ-ММ-ДД_ЧЧ-ММ-СС_площадка.mp4` (или `.webm`) — это местное время **окончания боя**.
- **▶ Повтор** — открывает последний клип. Кнопка неактивна во время записи.
- На экране повтора: −1 с, кадр назад/вперёд, пауза/пуск, +1 с, скорости 0,25× / 0,5× / 1×, «Зациклить», ползунок, звук. «Закрыть» возвращает к записи, камера **не перезапускается**.
- **Чистый экран** — только видео, без панелей (для зеркалирования на ТВ по проводу). Касание — пауза/пуск, двойное касание — выход.
- **Клипы** — список (новые сверху): смотреть, поделиться/скачать, закрепить (не удаляется автоочисткой), удалить.

### Управление
| Режим | Что работает |
|---|---|
| Кнопки на экране | всегда |
| Внешняя кнопка | клавиши (по умолчанию Пробел = «Бой/Стоп», R = «Повтор»; можно назначить любую), медиа-клавиши Play/Pause/Stop, «след./пред. трек» = «Повтор» |
| Голос (экспериментально) | слова «бой» и «стоп» |

## 4. Известные ограничения

- **iOS и камера.** Safari может приостановить камеру при сворачивании приложения или блокировке экрана. Приложение показывает предупреждение и кнопку «Переподключить камеру». Во время боёв не сворачивайте приложение. Экран удерживается включённым через Wake Lock (iOS 16.4+).
- **MediaRecorder и перемотка.** У записанных видео `duration` бывает `Infinity`. Приложение берёт длительность из сохранённых метаданных и применяет обходной приём (временная перемотка на очень большое значение). Покадровый шаг сделан через `currentTime ± 1/fps`: на фрагментированном MP4 в Safari шаг может иногда «залипать» на соседнем кадре.
- **60 к/с** запрашиваются как желаемые (`ideal`); камера может отдать 30. Фактическое значение показано вверху экрана записи и в настройках.
- **Формат.** Сначала пробуется `video/mp4`, затем `video/webm`. Chrome на Android поддерживает mp4 в MediaRecorder только в новых версиях, на старых будет webm.
- **Голос.** В Chrome распознавание речи идёт через интернет, работает нестабильно и может реагировать на шум зала. Микрофон конфликтует с записью звука, поэтому при включённом голосе видео пишется без звука. В установленном на iOS приложении распознавание речи, скорее всего, не заработает.
- **Внешние кнопки.** Bluetooth-кликеры бывают разных типов: одни эмулируют клавиатуру (работает), другие отправляют медиа-команды (работает только если браузер отдаёт их странице — это зависит от устройства). Кнопки громкости на самом телефоне страница не получает.
- **Pre-roll** (захват до команды «Бой») не реализован: в `recorder.js` есть отмеченная точка расширения.
- **Вывод на внешний экран** — реализован этап 1 (ноутбук/монитор через WebRTC в локальной сети), см. раздел 8. AirPlay/Chromecast (`remote-playback`) и Presentation API в `outputs.js` остаются заглушками, флаг `EXTERNAL_OUTPUT_ENABLED` для них по-прежнему `false`.
- **Хранилище.** Браузер может очистить данные сайта при нехватке места, если не дал «постоянное хранение». Приложение просит его автоматически; на iOS установка на главный экран помогает. Важные клипы сразу сохраняйте через «Поделиться».
- Если вкладку закрыть во время записи, клип восстановится при следующем запуске с пометкой «прерван» (потеряется не более ~1 секунды в конце).

### Что проверено и что нет
Код проверен на синтаксис, логику именования файлов и соответствие элементов страницы. **На реальных телефонах приложение не запускалось** (в среде разработки нет камеры). Поэтому обязательно пройдите чек-лист ниже на своих устройствах до соревнований. Отдельно требуют проверки: iOS-перемотка длительности, покадровый шаг на mp4 из Safari, медиа-клавиши вашего кликера, поведение при блокировке экрана.

## 6. Допущения

1. Основная установка — на главный экран; в обычной вкладке всё работает так же, но iOS быстрее освобождает память.
2. Время окончания боя = момент команды «Стоп». Post-roll добавляет хвост к видео, но не меняет имя файла.
3. Длительность клипа в метаданных (`durationMs`) включает post-roll.
4. Если выбранной камеры больше нет, используется задняя. Если микрофон недоступен, запись идёт без звука.
5. Приложение удерживает только один (последний) клип в памяти для мгновенного открытия повтора; остальные читаются из IndexedDB.
6. Пока запись идёт, настройки камеры (качество, fps, камера, звук) применяются после остановки.
7. Меньше 50 МБ свободного места — запись не начинается; меньше 300 МБ — предупреждение.
8. Минимальная автоочистка оставляет не менее одного незакреплённого клипа.
9. Скорости воспроизведения запоминаются между повторами в рамках сессии (сбрасываются при перезапуске).
10. Битрейт: 1080p30 — 8 Мбит/с, 720p30 — 5 Мбит/с, 60 к/с — ×1,6.

## 7. Структура

```
index.html            разметка всех экранов
styles.css            стили
manifest.webmanifest  PWA-манифест
sw.js                 Service Worker (офлайн, cache-first)
icons/                иконки 192, 512, apple-touch-icon 180
js/main.js            запуск, связывание модулей, переключение экранов
js/camera.js          камера, кадр для миниатюры, Wake Lock
js/recorder.js        конечный автомат записи, имя файла, pre-roll (точка расширения)
js/commands.js        шина команд START/STOP/TOGGLE/REPLAY + адаптеры: клавиши, Media Session, голос
js/store.js           IndexedDB: клипы, части записи, видео, автоочистка, восстановление
js/player.js          плеер: скорость, кадры, цикл, обход проблемы duration
js/outputs.js         OutputAdapter: local (работает) + заглушки remote-playback / presentation / viewer-link
display.html          страница экрана (открывается на ноутбуке)
js/external/          внешний экран: protocol, signaling, transport, phone-session, external-output, dialog
js/settings.js        настройки в localStorage и привязка к форме
js/ui.js              работа с DOM
```

Принцип: источники команд не знают про рекордер, рекордер не знает про источники. Всё общается через шину команд в `commands.js`.

## 8. Внешний экран (ноутбук / монитор), версия 1.1.0

Телефон остаётся пультом, видео показывается на ноутбуке. Связь напрямую по WebRTC в локальной сети: без интернета и без серверов. Функция по умолчанию **выключена**; пока она выключена, приложение работает как в версии 1.0.1 (модуль даже не загружается).

### Как подключить
1. На телефоне: **Настройки → Внешний экран → включить**, затем «Подключить / проверить связь» (или нажмите значок 🖥 на экране записи). Подключайтесь, когда запись не идёт.
2. На ноутбуке откройте адрес `…/display.html` (он показан в окне подключения), нажмите «Подключить», скопируйте код.
3. Перешлите код на телефон любым способом (мессенджер, заметки, AirDrop), вставьте в окно подключения, нажмите «Подключиться».
4. Скопируйте код-ответ с телефона, вставьте на ноутбуке, нажмите «Применить ответ». Появится «Подключено».
5. «Проверка связи (10 МБ)» покажет скорость, задержку и тип соединения.

Камера телефона для подключения не используется: коды передаются только текстом. После разрыва связи обмен кодами нужно повторить.

### Как это работает в зале
- После каждого боя клип сам уходит на ноутбук в фоне (настройка «Заранее отправлять…»), **не показываясь**. Индикатор 🖥 на экране записи: ✓ клип на экране, % идёт передача, ⏸ передача на паузе из-за записи.
- Во время записи передача автоматически встаёт на паузу и продолжается после, с того же места.
- «▶ Повтор» мгновенно показывает клип на ноутбуке, если он уже передан. Если нет, повтор идёт на телефоне, а когда клип дойдёт, показ переносится на экран с того же места.
- Кнопка «Показ: внешний экран / телефон» в плеере переключает вывод.
- Телефон показывает таймлайн по данным с ноутбука; своё видео не играет (если не включено «Показывать видео и на телефоне»).
- Если «Бой» приходит во время повтора, повтор закрывается, запись стартует, на ноутбуке «Ожидание повтора».
- При потере связи повтор продолжается на телефоне с того же места.

### Ограничения
- Гостевые Wi-Fi с «изоляцией клиентов» блокируют прямое соединение. Решение: общая сеть без изоляции или точка доступа на телефоне.
- Покадровая точность на ноутбуке ограничена браузером (шаг 1/fps от показанного кадра). Расхождение с запрошенным кадром возможно.
- Уже отправленные в буфер части (до ~1 МБ) доходят и после начала записи.
- Клип хранится на ноутбуке в памяти страницы (до 3 клипов); при перезагрузке страницы клипы нужно отправить заново.
- Проверка целостности только по размеру клипа.
- ТВ с браузером без поддержки WebRTC не подойдёт: для них позже планируются AirPlay/Chromecast.

### Что проверено и что нет
Проверено автоматически (в среде разработки, без браузеров и телефонов):
- синтаксис всех файлов, ссылки на элементы страницы;
- сквозной тест «телефонный модуль ↔ код страницы display.html» через эмуляцию WebRTC (node-datachannel): подключение текстовыми кодами, два канала, heartbeat, «Проверка связи», передача клипа 6 МБ с паузой на время «записи» и докачкой, команды show / seek / rate / loop / mute / pause / step / hide, состояние с экрана, разрыв связи и переподключение без повторной передачи клипа;
- логика приложения: сопоставление команд плеера командам экрана, перенос показа на экран после доставки клипа, продолжение на телефоне при потере связи, очередь отправки клипов (12 автотестов с имитацией).

**Не проверено на реальных устройствах:** работа в Safari на iPhone и Chrome на Android, реальная локальная сеть (в том числе mDNS-адреса и изоляция клиентов), скорость передачи в вашем зале, воспроизведение видео и точность покадрового шага на ноутбуке. Пройдите чек-лист ниже.

### Чек-лист (внешний экран)
- [ ] Подключение iPhone/Android ↔ ноутбук без интернета; «Проверка связи» показывает скорость
- [ ] После боя 🖥 меняется на ✓ (клип передан); «Повтор» сразу показывает его на ноутбуке
- [ ] Передача клипа 30 с в 1080p: засеките время; во время передачи запустите запись: 🖥 ⏸, запись не страдает (длительность и плавность в норме), после стопа передача продолжается
- [ ] Пауза, 0,25×/0,5×/1×, шаг кадра, ±1 с, ползунок, цикл, звук работают на ноутбуке; таймлайн на телефоне следует за ним
- [ ] «Повтор» сразу после боя, пока клип ещё передаётся: открывается на телефоне, затем переносится на экран
- [ ] «Бой» во время повтора: ноутбук показывает «Ожидание повтора», запись идёт
- [ ] Выключить Wi-Fi на ноутбуке: повтор продолжается на телефоне
- [ ] Выключить «Внешний экран» в настройках: приложение работает как раньше
